# NELLWICK AI Film Studio

A new, reusable filmmaking workspace. This repository is independent of KINETIX and the NELLWICK storefront.

## Product direction

- Next.js frontend deployed on Vercel.
- GitHub is the source-code repository.
- Supabase provides authentication, PostgreSQL and metadata storage.
- Google Drive is the primary store for uploaded/generated videos and other large media.
- Kaggle and Google Colab are interactive GPU notebook workers, not permanent backend servers.
- The first actual generation adapter is Wan 2.1 T2V 1.3B through Diffusers. Other models are listed as research candidates and are not falsely shown as ready.

## Current delivery scope

This repository is a working foundation with a cinematic dashboard, project/episode CRUD, media library actions (rename, open, download, tags, favourites, project assignment, safe trash/restore), Google Drive OAuth, chunked Drive uploads, Supabase schema/RLS, worker tokens, a leased per-shot checkpoint queue, Kaggle and Colab notebooks, and a Wan 2.1 notebook worker that saves clips to Drive and registers assets. Browser upload-session state is not yet persisted across a full page reload.

The screenplay director, character/continuity manager, storyboard approval UI, multi-track editor, Shorts selection, image generation and TTS are scaffolded/product-planned, not yet finished modules. The current worker does not create a complete eight-minute story from a sentence. It can generate up to 120 short shots from a production manifest and concatenate them in order. At five seconds each, 96 shots are needed for approximately eight minutes of raw shot runtime before trimming; this requires a substantial number of model generations and may span multiple notebook sessions. Dialogue, music and sound design are not yet generated by this first adapter.

## 1. Prerequisites

- Node.js 20.9 or newer.
- Git and a GitHub account.
- Vercel account.
- Supabase account and a new project for this app.
- Google Cloud project with the Google Drive API enabled and an OAuth 2.0 Web application client.
- Kaggle and/or Google Colab account with GPU access available for the session.

No paid API key is required by the initial notebook worker. Free GPU access is not guaranteed and model generation can be slow.

## 2. Create the app locally (Windows PowerShell)

Extract the ZIP, open PowerShell in the `nellwick-ai-film-studio` folder, then run:

```powershell
npm install
Copy-Item .env.example .env.local
```

Open `.env.local` and fill in the Supabase and Google variables. Generate the token encryption key:

```powershell
$bytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
$TOKEN_ENCRYPTION_KEY = ([Convert]::ToHexString($bytes)).ToLower()
$TOKEN_ENCRYPTION_KEY
```

Paste that value into `TOKEN_ENCRYPTION_KEY`. Keep `.env.local` private; it is ignored by Git.

Then run:

```powershell
npm run dev
```

Open `http://localhost:3000`.

## 3. Supabase setup

1. Create a new Supabase project. Keep it on the Free plan during the prototype.
2. Open SQL Editor and run `database/migrations/0001_initial_schema.sql`.
3. Copy the Project URL and anon/publishable key into `.env.local`.
4. Copy the service-role key into `SUPABASE_SERVICE_ROLE_KEY`. It must only exist in server environment variables. Never prefix it with `NEXT_PUBLIC_`.
5. In Supabase Authentication → URL Configuration, add `http://localhost:3000` as a development redirect URL if you use email confirmation.
6. Email/password sign-up is available at `/login`.

Supabase Free currently includes 500 MB database, 1 GB file storage and projects may pause after one week of inactivity. Its Free Storage per-file size limit is 50 MB. Keep generated video masters in Google Drive, not Supabase. Check the live Supabase pricing/usage page because quotas can change.

## 4. Google Drive OAuth setup

1. In Google Cloud Console create/select a project.
2. Enable **Google Drive API**.
3. Configure the OAuth consent screen. Add your own Google account as a test user while the app is in testing mode.
4. Create an OAuth Client ID of type **Web application**.
5. Add this authorised redirect URI:
   - Local: `http://localhost:3000/api/drive/callback`
   - Deployed: `https://YOUR-VERCEL-DOMAIN/api/drive/callback`
6. Put the OAuth client ID and secret into `.env.local`, and set `GOOGLE_REDIRECT_URI` to the exact redirect URI you configured.
7. Sign into the studio and open Settings → Connect Google Drive.
8. Approve the requested `drive.file` scope. The app creates a `NELLWICK AI FILM STUDIO` folder in your Drive.

The server requests offline OAuth access and encrypts the refresh token with `TOKEN_ENCRYPTION_KEY`. If Google does not return a refresh token on a later consent, the app retains the existing encrypted token. While an external OAuth consent screen is in Testing mode, Google may expire refresh tokens after seven days for non-basic scopes; for a persistent personal production connection, configure the consent screen appropriately and review Google verification requirements. To revoke access, remove the app from your Google Account's third-party access settings.

## 5. Push to GitHub

Create an empty repository named `nellwick-ai-film-studio`, then in PowerShell run:

```powershell
git init
git add .
git commit -m "Build NELLWICK AI Film Studio foundation"
git branch -M main
git remote add origin https://github.com/YOUR-GITHUB-USERNAME/nellwick-ai-film-studio.git
git push -u origin main
```

Do not commit `.env.local`, worker tokens or Google credentials.

## 6. Deploy to Vercel

1. Import the GitHub repository in Vercel.
2. Set the production environment variables from `.env.example`.
3. Set `NEXT_PUBLIC_APP_URL` to your Vercel URL.
4. Set `GOOGLE_REDIRECT_URI` to `https://YOUR-VERCEL-DOMAIN/api/drive/callback`.
5. Add the exact same production callback URL in Google Cloud Console.
6. Redeploy after saving environment variables.

Vercel functions are for quick application/API operations only; do not run video generation or large video assembly inside a Vercel function. The notebook workers do GPU compute and upload media to Drive.

## 7. Run the first worker

1. In the deployed Studio, sign in.
2. Go to Settings and connect Google Drive.
3. Go to Settings → Create notebook token. Copy it once; it is only displayed once and expires after 30 days.
4. Open `workers/colab/NELLWICK_Colab_Worker.ipynb` in Google Colab, or `workers/kaggle/NELLWICK_Kaggle_Worker.ipynb` in Kaggle.
5. Enable GPU. In Kaggle, enable Internet as well. Replace `YOUR-GITHUB-USERNAME` in the notebook's `REPOSITORY_URL` cell with your GitHub username/repo.
6. Run the notebook cells in order. Enter the Vercel URL and paste the worker token when prompted.
7. Queue a 2-second test sequence first from Production → New shot job. Check Drive and the Media Library before increasing duration or shot count.

The notebook installs Python packages but does not intentionally replace the preinstalled CUDA PyTorch. It downloads the model weights on first use. That download may be several GB and must fit in the notebook session's disk and network allowance. Test a 2-second clip first; actual runtime, memory and output quality must be measured on the GPU allocated to your account.

## 8. Model and quality constraints

Read `docs/MODEL_RESEARCH.md` before enabling any model. The first adapter is a text-to-video baseline, not a complete film generator. It is tuned for short 480p clips. Kaggle free GPU allocation and Colab free GPU access can vary, sessions can end, and long films require many shots. The system saves completed-shot checkpoints in Supabase and Drive so another notebook session can reuse finished clips. If a session is interrupted during model inference, that unfinished shot may need to be generated again. The system cannot make free GPUs unlimited or guarantee a daily finished-film count.

## 9. Security notes

- Supabase service-role key and Google OAuth client secret stay server-side.
- Refresh tokens are AES-256-GCM encrypted at rest in the `integrations` table.
- Notebook tokens are random, shown once, hashed in Supabase and expire after 30 days.
- Worker routes verify the token and limit work to that token owner's jobs.
- Use only original fictional characters or assets you have permission to use. Do not impersonate real people.
- The Colab notebook is an interactive compute worker only. It does not open a public port, serve media or run a permanent server.
